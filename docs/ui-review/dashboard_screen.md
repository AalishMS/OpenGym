# Dashboard screen

Reviewed 2026-10-02. Scope: desktop Dashboard and all dashboard tiles. Dashboard is intentionally unavailable in the compact shell (`lib/app_shell.dart:348`). Outdated screenshots were excluded.

## Findings

- **DB01 · Medium · Code-confirmed — plan rows have no 48dp minimum.** The tappable `InkWell` has only 4dp top/bottom padding around 10/9sp text and a 22dp marker (`lib/widgets/dashboard/plan_status_tile.dart:30`, `lib/widgets/dashboard/plan_status_tile.dart:34`, `lib/widgets/dashboard/plan_status_tile.dart:39`, `lib/widgets/dashboard/plan_status_tile.dart:50`, `lib/widgets/dashboard/plan_status_tile.dart:61`). Normal short rows are below 48dp. Give each row a minimum height of 48dp without enlarging the marker. Exact size with production fonts is unverified.
- **DB02 · Medium · Code-confirmed — Resume can open a different workout.** The last-session panel labels its action Resume regardless of completion (`lib/screens/dashboard_screen.dart:195`, `lib/screens/dashboard_screen.dart:200`). It opens only the matching plan (`lib/screens/dashboard_screen.dart:202`, `lib/screens/dashboard_screen.dart:267`), without the displayed session's week. Workout initialization chooses a draft or appends a new week after completed sessions (`lib/screens/workout_screen.dart:107`). Use View workout for a completed session, and pass the actual draft identity/week for Resume. Test renamed/deleted plans too.
- **DB03 · Medium · Code-confirmed — sparkline has no accessible representation of its series.** The chart is `CustomPaint` with no semantic series/summary (`lib/widgets/dashboard/progression_sparkline.dart:63`); visible text supplies only min/max and overall delta (`lib/widgets/dashboard/progression_sparkline.dart:82`, `lib/widgets/dashboard/progression_sparkline.dart:89`). A rise followed by a fall is unavailable as an accessible trend. Add a concise labeled trend summary or a data-list alternative. Actual screen-reader navigation is unverified; the heatmap already uses per-cell tooltips (`lib/widgets/dashboard/frequency_heatmap.dart:134`).
- **DB04 · Low · Code-confirmed — legacy typography and capitalization differ from the theme.** All-uppercase panel/KPI labels (`lib/screens/dashboard_screen.dart:100`, `lib/screens/dashboard_screen.dart:159`) and monospaced 8–10sp ordinary labels (`lib/widgets/dashboard/plan_status_tile.dart:48`, `lib/widgets/dashboard/frequency_heatmap.dart:174`, `lib/widgets/dashboard/dashboard_panel.dart:129`) conflict with the sans, sentence-case direction. Use theme label/body roles and reserve training-data typography for figures.

| --- | --- |
| Visual consistency | Panels use `AppSpacing`, `AppRadius.card`, and solved theme grounds (`lib/widgets/dashboard/dashboard_panel.dart:32`). DB04 is the main inconsistency. No screen-level hardcoded hex colors or literal radii found. Heatmap cell geometry is intentional chart geometry, not missing page-spacing tokens. |
| Hierarchy | KPI row, last session, activity/records, then plans/progression form a clear sequence (`lib/screens/dashboard_screen.dart:84`, `lib/screens/dashboard_screen.dart:97`, `lib/screens/dashboard_screen.dart:121`). DB02 makes the prominent session action misleading. |
| States | Whole-page empty state has New plan and Choose a split (`lib/screens/dashboard_screen.dart:302`, `lib/screens/dashboard_screen.dart:314`); empty panels have explicit placeholders (`lib/screens/dashboard_screen.dart:115`, `lib/screens/dashboard_screen.dart:127`, `lib/screens/dashboard_screen.dart:226`). Reads are local and synchronous. Empty-state `Column` lacks scrolling (`lib/screens/dashboard_screen.dart:284`); overflow on a very short desktop window is **unverified**. |
| Ergonomics | DB01 is the target-size defect. Labeled buttons inherit 48dp minima. Heatmap cells are 12dp tooltip surfaces (`lib/widgets/dashboard/frequency_heatmap.dart:112`, `lib/widgets/dashboard/frequency_heatmap.dart:134`), not workout actions; a larger data alternative would help touch inspection. No number inputs. |
| Accessibility | Solved accent ramps and foreground helpers are used. DB03 lacks chart detail; DB04's small text is a readability concern even when contrast is correct. Existing large-text layout tests do not prove chart comprehension. |
| Small/large screens | Width-based stacking and a maximum content width exist (`lib/screens/dashboard_screen.dart:74`, `lib/screens/dashboard_screen.dart:80`, `lib/screens/dashboard_screen.dart:251`). Existing tests cover populated layouts at 390/1200dp and 1/1.3/2x text (`test/screen_layout_test.dart:192`); short heights and production-font clipping remain unverified. |
