# Workout screen

Reviewed 2026-10-02. Scope: active/completed weeks, timer, plan/week navigation, exercise log, set keypad, finish/discard, week dialogs. Old screenshots excluded.

## Findings

- **W01 · High · Verified by widget probe — completed workouts cannot scroll.** `IgnorePointer(ignoring: session.isCompleted)` wraps the entire `CustomScrollView` (`lib/screens/workout_screen.dart:874`, `lib/screens/workout_screen.dart:894`). A completed 20-exercise fixture had **2,615.88dp of scroll extent**, but a vertical drag left its offset at **0dp**; the hit test excluded the scrollable. Restrict read-only behavior to edit actions, allowing vertical scrolling and access to lower exercises.
- **W02 · High · Code-confirmed — navigation can silently lose draft changes.** Reordering and confirmed exercise deletion only update in-memory state (`lib/screens/workout_screen.dart:604`, `lib/screens/workout_screen.dart:614`, `lib/screens/workout_screen.dart:717`). Plan-tab replacement never saves (`lib/screens/workout_screen.dart:1058`), nor does title-swipe replacement (`lib/screens/workout_screen.dart:1283`, `lib/screens/workout_screen.dart:1295`). There is no PopScope/system-back save hook; the custom Back starts `_autoSave` without awaiting it and pops immediately (`lib/screens/workout_screen.dart:768`). Persist these mutations and centralize an awaited save-before-leave path, including system back and plan switching. Actual disk-failure/data-loss sequences remain unverified; the missing persistence paths are visible in code.
- **W03 · Medium · Code-confirmed — autosave/timer failures lack user feedback.** `_autoSave` awaits storage with no catch (`lib/screens/workout_screen.dart:188`, `lib/screens/workout_screen.dart:203`), and several callbacks discard its future (`lib/screens/workout_screen.dart:460`, `lib/screens/workout_screen.dart:517`, `lib/screens/workout_screen.dart:974`). Timer writes likewise lack a busy/error state (`lib/screens/workout_screen.dart:268`, `lib/screens/workout_screen.dart:280`, `lib/screens/workout_screen.dart:318`). Finish already catches failures (`lib/screens/workout_screen.dart:362`), so extend that recovery model to saves/timer actions and avoid claiming data is saved before completion.
- **W04 · Medium · Code-confirmed — Finish depends on an unexplained prior timer start.** Sets can be entered before Start, but Finish remains disabled until `session.hasStarted` (`lib/screens/workout_screen.dart:1000`). The enabled Start action is in the top app bar (`lib/screens/workout_screen.dart:822`), while disabled Finish is at the bottom. Add explanatory status beside Finish, start the timer when starting the workout from Home, or support logging an untimed workout. The best product choice needs user validation.
- **W05 · Medium · Code-confirmed — invalid week input gives no response.** Rename week requests a numeric keyboard (`lib/widgets/workout/workout_dialogs.dart:540`, `lib/widgets/workout/workout_dialogs.dart:546`), but has no digits formatter, Done-submit handling, or inline error. Rename silently does nothing for blank/zero/non-integer input (`lib/widgets/workout/workout_dialogs.dart:565`). Add validation/error semantics and keyboard submission.
- **W06 · Low · Code-confirmed — week utility copy/type remains inconsistent.** Prompt-prefixed messages at `lib/screens/workout_screen.dart:635`, `lib/screens/workout_screen.dart:678` and uppercase DELETE/monospaced ordinary dialog labels at `lib/widgets/workout/workout_dialogs.dart:483`, `lib/widgets/workout/workout_dialogs.dart:492`, `lib/widgets/workout/workout_dialogs.dart:533` conflict with sentence-case interface copy. Replace ordinary styles with theme roles and use `AppSpacing` for the 8dp insets at `lib/screens/workout_screen.dart:1120`.
