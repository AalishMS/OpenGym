# Plan editor screen

Reviewed 2026-10-02. Scope: create/edit, name/color inputs, exercise cards, prescribed sets, picker, save/discard. Outdated screenshots excluded.

## Findings

- **P01 · Medium · Code-confirmed — saving has neither busy nor failure state.** `_savePlan` awaits provider mutations without a guard or catch (`lib/screens/plan_editor_screen.dart:116`, `lib/screens/plan_editor_screen.dart:166`). The custom Save control remains enabled from name validity alone (`lib/screens/plan_editor_screen.dart:46`, `lib/screens/plan_editor_screen.dart:490`). Prevent repeated submissions, announce saving, preserve the draft on failure, and report a retryable error. Duplicate records under slow storage are a risk, not a reproduced outcome.
- **P02 · Medium · Code-confirmed — prescription summary ignores text scaling.** The standalone `RichText` supplies no `textScaler` (`lib/screens/plan_editor_screen.dart:801`); its 13/10sp data styles are fixed (`lib/screens/plan_editor_screen.dart:807`, `lib/screens/plan_editor_screen.dart:813`). Flutter's `RichText` defaults to no scaling. Use `Text.rich` or pass `MediaQuery.textScalerOf(context)` and allow sufficient height. This remains a defect even if an overflow test passes.
- **P03 · Medium · Verified shared-widget geometry — number targets can be narrower than 48dp.** Nested 16dp page, 12dp panel, and 12dp set-table gutters (`lib/screens/plan_editor_screen.dart:323`, `lib/widgets/dashboard/dashboard_panel.dart:112`, `lib/screens/plan_editor_screen.dart:705`) leave approximately 238dp at a 320dp viewport. At that table width the weight target measured **41.9 × 48dp**. Columns use fixed/flex allocation without a weight/rep minimum (`lib/widgets/workout/set_entry_table.dart:363`, `lib/widgets/workout/set_entry_table.dart:374`, `lib/widgets/workout/set_entry_table.dart:390`). The probe tested the table geometry; full-screen size with production fonts is unverified. Use fewer columns, stacked editing, or horizontally scrollable minimum-width columns.
- **P04 · Medium · Code-confirmed — Back icon has no accessible name.** Header Back is an `InkWell` around an unlabeled chevron (`lib/screens/plan_editor_screen.dart:472`, `lib/screens/plan_editor_screen.dart:478`), unlike other screens' tooltip-bearing `IconButton` controls. Use `AppIconButton(label: 'Back')` or explicit button semantics/tooltip. Its 48dp size is already correct.
- **P05 · Low · Code-confirmed — legacy copy/type bypasses the interface roles.** CREATE/EDIT PLAN, PLAN NAME/COLOR, SAVE and prompt-prefixed messages remain (`lib/screens/plan_editor_screen.dart:123`, `lib/screens/plan_editor_screen.dart:314`, `lib/screens/plan_editor_screen.dart:333`, `lib/screens/plan_editor_screen.dart:353`, `lib/screens/plan_editor_screen.dart:505`). Name entry forces character capitalization and explicit monospace (`lib/screens/plan_editor_screen.dart:535`, `lib/screens/plan_editor_screen.dart:537`). Use sentence case and theme title/body/label roles; keep the brand prompt only in the wordmark.
- **P06 · Low · Code-confirmed — destructive footer action uses ordinary muted ink.** Delete exercise uses `textSecondaryColor` (`lib/screens/plan_editor_screen.dart:853`, `lib/screens/plan_editor_screen.dart:856`). Use the error role and a visible label/tooltip so its consequence is distinct. The confirmation at `lib/screens/plan_editor_screen.dart:233` is already present.
