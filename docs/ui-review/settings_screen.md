# Settings screen

Reviewed 2026-10-02. Scope: appearance, workout preferences, sample/backup/import/clear, account status/sign-out, updates, tutorial entry and about. Outdated screenshots excluded.

## Findings

- **S01 · Medium · Code-confirmed — async actions are not guarded or visibly busy.** Sample load and import dismiss confirmation before awaiting work (`lib/screens/settings_screen.dart:624`, `lib/screens/settings_screen.dart:822`); clear awaits work with its button still enabled (`lib/screens/settings_screen.dart:927`). `_runSettingsAction` handles errors but exposes no busy state (`lib/screens/settings_screen.dart:130`). Add action-specific progress/disable guards, especially around data replacement and clearing. Repeat-click concurrency and its data consequences are unverified.
- **S02 · Medium · Code-confirmed — settings has no desktop reading-width cap.** Body is a full-width `SingleChildScrollView > Column` (`lib/screens/settings_screen.dart:179`). Rows put content in `Expanded` and a trailing chevron at the far edge (`lib/screens/settings_screen.dart:561`, `lib/screens/settings_screen.dart:569`, `lib/screens/settings_screen.dart:592`); the theme segmented control expands too (`lib/screens/settings_screen.dart:369`). Unlike History/Stats, this can span the whole desktop pane. Center a capped content column using a shared width role; exact preferred width requires current visual validation.
- **S03 · Low · Code-confirmed — header/appearance type disagrees with sibling screens.** Settings title uses accent-colored explicit 16sp monospace over a mesh header (`lib/screens/settings_screen.dart:166`, `lib/screens/settings_screen.dart:169`); Accent color/name use 12/10sp monospace (`lib/screens/settings_screen.dart:418`, `lib/screens/settings_screen.dart:427`). Other ordinary screen titles use neutral `titleLarge`. Align header and label roles with the theme; reserve monospace for actual data.
- **S04 · Low · Code-confirmed — spacing and accent-ground roles drift.** Literal page/section/control gaps duplicate spacing tokens (`lib/screens/settings_screen.dart:180`, `lib/screens/settings_screen.dart:355`, `lib/screens/settings_screen.dart:365`, `lib/screens/settings_screen.dart:393`, `lib/screens/settings_screen.dart:994`). The successful manual-update snackbar paints `accentColor` as its ground (`lib/screens/settings_screen.dart:118`, `lib/screens/settings_screen.dart:125`) instead of `accentFillColor`. It uses `onColor(ground)`, so this is a **role inconsistency**, not a measured contrast failure. Use the fill/on-accent pair and spacing tokens.
- **S05 · Low · Code-confirmed — sample-data copy understates replacement.** The row says “Add sample plans and workouts” (`lib/screens/settings_screen.dart:216`), while confirmation says it replaces active-split data (`lib/screens/settings_screen.dart:615`) and the callback clears first (`lib/screens/settings_screen.dart:634`). State “Replace current split with sample data” before opening the dialog, with a distinct destructive treatment.
